`Transition.Boundary` is the compound API for bounds-driven transitions.

- `Transition.Boundary`
- `Transition.Boundary.Target`

## Transition.Boundary

Use this for both pressable and passive boundary registration.

When `onPress` is present, it renders as a pressable boundary. When `onPress` is omitted, it renders as a passive view boundary.

```tsx
// Passive boundary
<Transition.Boundary id="hero">
  <Image source={heroImage} style={styles.hero} />
</Transition.Boundary>

// Pressable boundary
<Transition.Boundary
  id="hero"
  onPress={() => navigation.navigate("Detail")}
>
  <Image source={heroImage} style={styles.hero} />
</Transition.Boundary>
```

This is the default recommendation for new code.

## Transition.Boundary.Target

Use this when the measured element is nested inside the owner.

```tsx
<Transition.Boundary id={item.id} onPress={openItem} style={styles.row}>
  <Transition.Boundary.Target style={styles.artTarget}>
    <Image source={item.image} style={styles.artwork} />
  </Transition.Boundary.Target>

  <View style={styles.copy}>
    <Text>{item.title}</Text>
  </View>
</Transition.Boundary>
```

It does not take its own `id`. It inherits the surrounding boundary owner and changes which descendant gets measured.

`Transition.Boundary.Host` is deprecated. Escaped boundaries go to their screen's overlay on their own and follow their scroll views while they are out, so there is no host to place. It still renders for now and warns in development; remove it.

## Boundary Config Props

Boundary components share the same configuration props:

- `id`
- `group`
- `anchor`
- `scaleMode`
- `target`
- `method`
- `enabled`
- `handoff`
- `escapeClipping` (deprecated, no effect: see [Escaping clipping](/shared-elements#escaping-clipping))

They keep the wrapped component props as well. The root `Transition.Boundary` accepts `onPress` for pressable usage.
